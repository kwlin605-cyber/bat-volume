# 球棒體積／開發者文件

這是一個 React／TypeScript 靜態網站。ANC 的解析、鋸片掃掠、切線、尺寸與體積在瀏覽器 Worker 計算；重量、格式化、排序及報告沿用共用領域結果。沒有負責計算或保存上傳檔案的後端服務。

## 閱讀方式

1. 跨模組任務先讀 [架構總覽](架構總覽.md)。
2. 依下表找主題文件，沿實作入口核對 Code、Tests 與需求。
3. 文件描述目前行為；[開發偏好](../開發偏好.md)與 [UIUX 規範](UIUX設計規範.md)定義修改時應遵守的方向。既有實作與規範有落差時，先查明並列入待辦，不把落差寫成已完成。

同一事實由一篇主題文件完整定義，其他文件引用。文件不複製整段 Code、不寫 Changelog；舊 `.aistudio` 計畫、示意圖片及對話不能單獨作為目前契約的依據。

## 適用驗證入口

在專案根目錄執行：

| 修改範圍 | 適用檢查 |
| --- | --- |
| 規則、文件 | 相對連結／錨點、內容與 Code／Tests 對照、Git 範圍檢查；不為文案調整重跑全部程式測試 |
| 核心、服務、狀態或格式 | 先跑相關 `npm test -- tests/檔名.test.ts`，再依跨模組風險執行 `npm test` 與 `npm run build` |
| React／型別 | `npm run lint` 為 TypeScript 檢查；正式建置也會執行型別檢查，沒有另設 ESLint 工作 |
| UI／共用樣式／3D | 相關測試、`npm run build`，加上實際瀏覽器的窄／寬畫面、操作、載入與錯誤狀態檢查 |
| 本機啟動 | `npm test -- tests/launcher.test.ts` 在 Windows 執行；本機 `npm run build` 後核對 `啟動.cmd` |
| 報告 | 報告與列印測試、建置；排版變更另檢查瀏覽器預覽、PDF 及必要的 Excel 實際列印 |
| Pages 建置／部署 | `npm test`、`npm run build -- --base=/bat-volume/`；核對實際 workflow，不能將本機結果稱為線上 Actions 已通過 |

若最後做了 Pages 子路徑建置，而要交付本機啟動，需再執行一般 `npm run build`。測試與建置是否足夠依具體變更判斷，不以固定測試數量代表涵蓋完整。
