# 啟動、建置與部署

## 執行環境與開發

建置與測試以 Node.js 24 為建議環境，與 [Actions](../../.github/workflows/deploy.yml) 一致；[package.json](../../package.json) 沒有另外宣告 engines 限制。依賴由 lockfile 鎖定，新的開發環境先在根目錄執行 `npm ci`。

| 命令 | 實際用途 |
| --- | --- |
| `npm run dev` | Vite 開發服務，預設對外綁定 0.0.0.0:3000，可熱更新 |
| `npm test` | Vitest 執行測試 |
| `npm run lint` | `tsc -b` 型別檢查，不是 ESLint |
| `npm run build` | TypeScript 檢查後 Vite 正式建置至 `dist` |
| `npm run preview` | Vite 正式產物預覽，預設 0.0.0.0:3000 |

主機與 port 來源見 [vite.config.ts](../../vite.config.ts)及 package scripts。開發／preview 的綁定方式與下面只聽本機的 `啟動.cmd` 服務不同。

## Windows 啟動檔

[啟動.cmd](../../啟動.cmd) 切到專案目錄，依序尋找專案 `runtime/node.exe`、PATH、使用者工具位置及一般 Node 安裝位置，再執行 [launch.cjs](../../scripts/launch.cjs)。找不到環境時，以 Windows PowerShell 用 UTF-8 讀取 [messages.json](../../scripts/messages.json)，顯示訊息並保留視窗。支援中文及有空格的專案路徑。

`launch.cjs` 要求已有 `dist/index.html`，不執行 npm install 或 build。它掃描 4173–4193 的健康端點，核對 application 與專案 root；同一份專案已有服務就重用，否則啟動隱藏的背景服務，再以預設瀏覽器開啟網址。啟動失敗會保留可讀錯誤，server log 位於 `scripts/server.log`。

[serve.cjs](../../scripts/serve.cjs) 只綁定 `127.0.0.1`，預設 4173，port 已用時往後尋找。只提供 `dist` 的 GET／HEAD 檔案，處理 MIME、路徑越界與健康端點；不做 ANC 計算、不保存用戶檔案。它讀取磁碟上的建置內容，不會因啟動檔已成功就代表程式碼已是最新。

修改程式後先 `npm run build`，再重新整理已開頁面或雙擊啟動檔。相同來源網址的瀏覽器資料可以還原；port 改變可能使用另一份瀏覽器保存空間，見 [資料保存與設定](資料保存與設定.md)。

## 本機與 GitHub Pages 建置

[vite.config.ts](../../vite.config.ts) 的一般 base 為 `./`，適合本機啟動服務。GitHub Pages 工作流程會覆寫為 repository 子路徑，本專案對應檢查命令：

```sh
npm test
npm run build -- --base=/bat-volume/
```

Pages 產物的資源路徑不能直接當作根路徑本機啟動版本。若最後做的是上述檢查，交付 `啟動.cmd` 使用前要再執行一般 `npm run build`。

`dist` 與 `node_modules` 不納入 Git，不能把修改來源檔視為已自動更新部署網站；本機既有套件也不能代替新環境的鎖定安裝驗證。

## Actions 與發布效果

目前只有 [deploy.yml](../../.github/workflows/deploy.yml)：推送 main 或手動 dispatch 後，checkout、準備 Node 24、`npm ci`、`npm test`、按 repository 路徑 build，接著設定 Pages、上傳 artifact 並發布。沒有獨立的 pull request 測試觸發條件。

因此這個工作流程不只是測試，通過後會發布網站；實際觸發需在授權範圍內，不因本機測試通過而自行推送或發布。依 [工作規則](../../AGENTS.md)，Commit 由使用者操作。回報時分清楚本機檢查、遠端 Actions 與已發布狀態，沒有遠端執行證據時不能說線上已通過。

啟動測試在 Windows 執行，Pages 的 Ubuntu job 會略過該平台專屬案例；兩者驗證界線見 [測試與驗證](測試與驗證.md)。
