# 資料保存與設定

## 保存責任

[useBatchSession](../../src/hooks/use-batch-session.ts) 是目前批次與提交要求的協調入口；[batch-session.ts](../../src/services/batch-session.ts) 管理批次資料格式與不可變更新；[latest-session-storage.ts](../../src/services/latest-session-storage.ts) 提供序列化保存及 IndexedDB 實作。保存層不擁有另一份分析或 UI 狀態。

| 資料 | 位置與生命週期 |
| --- | --- |
| 最新批次的型號庫項目 | IndexedDB `bat-volume.session`，`current` store 的 `files`；保存各支 ID、名稱及完整來源參照，不保存型號庫 ANC 備份 |
| 最新批次的手動上傳項目 | 同一 `files` 記錄保存各支 ID、名稱、修改時間、上傳來源及原始 Blob，不保存原電腦路徑 |
| 各支已提交要求重量 | 同一資料庫的 `requirements`，附批次 ID，重量為 g |
| 顯示欄位 | 同一資料庫的 `display`，附批次 ID |
| 排序 | 本次開啟的 React 狀態，不保存；新增／移除部分資料沿用，重新開啟重置 |
| 材料、刀寬、直徑扣除量、長度／重量單位、棒壘分類 | 各自的 localStorage key，與檔案批次分開 |
| 分析結果與 3D 網格 | 記憶體，不保存為下次計算依據；依來源重新取得 File 後分析 |
| 報告預覽、頁碼與列印縮放 | 當次預覽元件，不寫入批次或全域偏好 |

資料庫名稱、版本及 keys 由 [session.ts](../../src/config/session.ts) 管理。重開同一瀏覽器與來源網址時讀取最新一批；新增／移除替換同一份資料，不累積歷史。不同來源網址（含不同 port）、瀏覽器或清除網站資料後不共用原保存內容。

目前檔案與顯示設定的保存格式為版本 2，讀取相容版本 1／2；IndexedDB 資料庫版本仍為 1。舊資料沒有來源紀錄時保留 Blob、各支 ID、要求重量與有效顯示設定，來源保持不明，不靠檔名推測廠商或自動改成型號參照。從型號庫重新加入會建立獨立項目，不自動合併舊資料或轉移其要求重量。

## 來源解析與重開計算

[file-origin.ts](../../src/services/file-origin.ts) 定義型號庫／手動上傳來源；[session-sources.ts](../../src/services/session-sources.ts) 將保存項目轉成可載入來源，交給既有有界分析佇列。每支保留獨立的批次項目 ID，型號庫的完整來源 ID 另用來找目前編譯版本的檔案，兩者不混用。

| 來源 | 重開或更改刀寬時的內容依據 |
| --- | --- |
| 型號庫 | 依完整來源 ID 查目前網站編譯的目錄，讀取該版本 ANC；同位置同名檔內容更新後，重新開啟會使用新版 |
| 手動上傳 | 以保存的 Blob 重建 File；更新內容須重新上傳 |
| 舊的無來源項目 | 繼續使用原保存內容，不自動對應型號庫 |

「目前版本」是已編譯／部署的網站，不直接讀使用者磁碟。專案內 ANC 改動後需重新建置；已開啟頁面須重新開啟或整理，才切換到新版本的型號目錄。

完整來源不存在，包括原檔被移除或改名／移動，該支回報「型號已移除，無法計算。」；下載失敗則回報型號載入失敗，不以舊 ANC 或其他同名型號接替。兩者皆為來源不可用狀態，不產生幾何、推算重量或 3D，但保留該項目與已提交要求；桌面仍可看到指定重量這項使用者輸入。來源重新可用後，重開即可重新載入。這與使用者主動移除資料列不同，後者會刪除該支要求。

以下是沒有可用保存資料時的值；有效舊偏好不會被新預設覆蓋。

| 項目 | 初始值／空白行為 | 權威來源 |
| --- | --- | --- |
| 參考密度 | null，沒有預設密度 | [config/weight.ts](../../src/config/weight.ts) |
| 木料體積 | 3725.6 cm³，可清空 | 同上 |
| 木料重量 | null，可輸入實測 g | 同上 |
| 實測重量誤差 | 0%；表單以空白呈現 0，空白套用為 0 | 同上及 [material-dialog.tsx](../../src/features/batch/material-dialog.tsx) |
| 鋸片寬度 | 5 mm；表單清空套用為 0，切回原始輪廓模式 | [blade-width.ts](../../src/domain/blade-width.ts)、對應保存服務 |
| 直徑扣除量 | 0 mm；空白套用為 0 | [diameter-allowance.ts](../../src/domain/diameter-allowance.ts) |
| 長度單位 | in；可切 cm 或雙單位 | [length-unit-storage.ts](../../src/services/length-unit-storage.ts) |
| 木料重量單位 | oz；可切 g 或雙單位，球棒預計重量仍為 g | [weight-unit-storage.ts](../../src/services/weight-unit-storage.ts) |
| 顯示欄位 | 全選六個數據欄位 | [batch-display.ts](../../src/domain/batch-display.ts) |
| 排序 | 木料重量升冪，先依棒壘分組 | 同上及 [row-order.ts](../../src/features/batch/row-order.ts) |
| 棒壘分界與順序 | 60 mm，壘球在前 | [grouping.ts](../../src/config/grouping.ts) |

各偏好服務位於 `src/services/*-storage.ts`。材料 JSON 保存版本目前為 3，讀取相容版本 1／2／3，版本 1 缺少誤差時補 null；有效清空的欄位仍保留空白。無效資料回落預設；讀寫例外回報不可保存，但本次記憶體操作仍可使用。各 key 與格式由對應模組管理，不在 UI 再另定一份。

## 新增、移除與還原

每次手動上傳建立獨立 ID，即使同檔名或內容相同仍可並存；型號庫只對相同完整來源去重，不影響其他同名來源或手動上傳。既有要求依各支 ID 保留。移除指定檔案會刪除其要求並取消該支載入／分析。清空或移除最後一支時，批次、要求、欄位與排序重置，材料及獨立偏好保留。手機選新檔案的替換行為見 [手機與電腦操作](手機與電腦操作.md)。

初次非同步還原會核對 intent；若使用者已新增、移除或清空，就忽略過期還原。檔案、要求與欄位以同一交易替換，單獨更新要求或欄位時核對批次 ID，避免寫到新批次。保存寫入序列讓較慢的舊保存不會覆蓋後續清空；一次失敗不會永久阻塞後續寫入。

要求或顯示設定更新只寫小資料，不重存檔案來源、不重新分析。型號文字下載與後續分析共用有界佇列；移除、清空、重新分析或卸載後，晚到的下載不能再啟動已取消項目的分析，也不能寫回舊結果。

## 草稿與套用

材料彈窗保存密度、體積、重量、誤差、刀寬、直徑扣除量及單位草稿；驗證成功後按套用才更新 App 與各保存服務，取消不提交草稿。其他入口如工具列的單位／分界／直徑控制有自己的提交時機，不能因共用外觀而改成同一種保存交易。

更改刀寬會重新分析目前全部檔案，但保留檔案 ID、要求與欄位設定。改材料或要求只更新重量推算；改直徑扣除量只影響顯示尺寸及相關排序。完整公式與顯示界線見 [切線、尺寸與重量](切線尺寸與重量.md)。

測試見 [測試與驗證](測試與驗證.md) 的批次／保存及設定類別。Node 中的保存替身不等同實際瀏覽器 IndexedDB、權限或儲存容量驗證。
