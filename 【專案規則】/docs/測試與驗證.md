# 測試與驗證

## 執行方式

測試位於 [tests](../../tests)，由 [vite.config.ts](../../vite.config.ts) 的 Vitest 設定以 Node 環境執行 `tests/**/*.test.ts`。完整命令、型別與建置入口見 [文件地圖](README.md#適用驗證入口)，不在每個主題重複維護執行流程。

修改前先核對既有保護，穩定 Bug 優先建立能因正確原因失敗的案例。先跑受影響測試，再依風險補整合或完整建置；不得為通過而跳過、刪除或放寬既有契約。已有效且對應同份內容的證據可以沿用，不因文件或無關修改機械式重跑。

## 計算驗證界線

圓柱、圓台與線性斜率使用可獨立求出的數值驗證，不只檢查有無產生輪廓或大致增減。完整掃掠案例檢查位於取樣格線之間的交點，防止再次把固定格線當成完整幾何。內建資料庫測試以原始刀路直接查詢若干非格線位置，交叉核對邊界；不是逐點實物量測。

`corpus` 的原始樣本與尺寸 JSON 保護程式交界、尺寸及握把辨識，不是機台切割認證；5 mm 案例另確認完整輪廓與握把。`blade-envelope` 對 `318-V2` 的案例保護目前多階尾料規則下的切點，不代表它是正確實物成品邊界。

`bat-geometry` 驗證生成網格前的輪廓點與頂點，不建立真實 WebGL 畫面；顯示用 Float32 不回寫領域數據。公式與網格測試通過不能取代刀具基準、實際尺寸、含水率或重量校準，見 [待辦與已知限制](待辦與已知限制.md)。

## 平台與操作驗證

- 保存測試的替身可驗證交易與排序契約，不能證明實際瀏覽器 IndexedDB、權限、容量或不同網址下的還原都可用。
- Worker 的替身可驗證排程與取消，不等同真實瀏覽器模組載入、網路時序或 Web Worker 資源行為。
- Node／靜態 React 輸出不是完整 DOM 操作；表格拖曳、自動捲動、Esc、失焦、dialog 焦點、觸控及跨斷點切換仍需實際瀏覽器。
- 3D 需核對整枝／切除模式、標記、旋轉／縮放、手機容器、WebGL 失敗及資源釋放；桌面瀏覽器的手機尺寸不等同實體手機效能測試。
- 報告需核對實際預覽、PDF 開啟及適用的 Excel 列印；Excel／印表機引擎可能改變分頁，不能只靠數字或 XML 斷言驗收視覺。
- Ubuntu Actions 不執行 Windows 專屬啟動案例；本機 Windows 通過也不能單獨證明遠端 Pages 已建置或發布。

## 回報與文件任務

回報需列命令或檢查範圍、結果、對應 commit／未提交狀態及尚未驗證部分。區分本機測試、實際瀏覽器、實機與遠端 Actions，不把曾經通過的數量寫成每次任務都執行過。

只修改 Markdown 時，檢查本地連結／錨點、來源檔與測試對照、規則移植範圍、過時／重複描述及 Git 差異。不要為這類可逆文件修改新增鏡像內容測試、重建網站或重跑無關功能；若文件改變了執行契約或附帶程式修改，另依受影響範圍驗證。
