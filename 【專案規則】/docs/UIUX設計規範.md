# UIUX 設計規範

本文件定義本網站的呈現與元件責任；一般程式品質見 [開發偏好](../開發偏好.md)，保存、選取與數值的操作契約由各主題文件定義。規範要求不能當作所有舊實作已符合的證明，現存落差見 [待辦與已知限制](待辦與已知限制.md)。

## 設計方向

維持簡潔的中性黑白灰、清楚對齊及合理留白，數字是畫面主角。桌面偏多檔比較與鍵盤／滑鼠，手機偏單支閱讀與觸控；同一用途保持可辨識的操作，不強制做成一樣的版面。

主要操作不因增加功能而被藏起；避免新增多餘卡片、診斷頁、長篇提示或每次都要確認的步驟。錯誤、未知與載入要可理解，但不把實作細節塞進使用者流程。空狀態應能回到型號庫或本機上傳，長檔名及窄／矮畫面不得遮住主要動作。

新共用色值與樣式沿用具名來源，不能各頁建立第二套主題；相同外觀但責任不同的元件可保留獨立狀態。現有 CSS、3D 材質與標記仍有局部色值，尚未全面集中。

目前以淺色中性樣式及繁體中文為主，沒有獨立英文或深色主題。不得把 Mumiopad 的品牌紫色、Material、Tauri、雙語或深淺主題條款直接當成本網站已實作的功能。

## 文字與可及性

網頁使用者文字、診斷、單位與格式用語由 [i18n/zh-TW.ts](../../src/i18n/zh-TW.ts) 管理，本機啟動訊息由 [scripts/messages.json](../../scripts/messages.json) 管理。改 key 前搜尋所有引用，技術 log、內部 ID 與測試描述不必偽裝成翻譯文案。

圖示操作保留可存取名稱，表單有對應 label，未知值不能以 0 假裝已知。保留焦點、鍵盤操作與錯誤提示；選取狀態可使用既有淡綠底與側線，分析狀態不只靠顏色傳達。動態效果沿用系統減少動態偏好。

數值顯示由既有格式 helper 管理；UI 或 renderer 不各自重新定義換算、取位或重量公式。列印可以有獨立字級，但保留同一數據與欄位語意。

## 操作、彈窗與保存

目前各功能使用自己的彈窗或抽屜，桌面設定／預覽常用原生 `dialog`，沒有一個管理所有功能交易的通用 Modal。擴充時可重用呈現或組合內容，不能為外觀一致而把所有功能塞進大量旗標控制的元件。

共用呈現只負責框體、控制與可操作狀態；材料驗證、批次提交、取消、檔案移除與報告取消仍由功能負責。材料設定為草稿按套用，工具列的單位／分界控制與手機要求重量另有提交時機，見 [資料保存與設定](資料保存與設定.md)與[操作文件](手機與電腦操作.md)。

本網站原有 Esc、點外部及返回行為照功能契約處理，不套用 Mumiopad PC 的「所有彈窗禁止 Esc／遮罩關閉」產品規則。一般設定取消不得偷偷保存草稿；處理中避免重複送出，關閉應取消尚未完成的報告或釋放適用資源。

3D 共用同一個 `BatPreview` 與幾何建立入口，手機只改容器與載入時機。計算使用的完整輪廓不能為顯示效能而被有損刪點；若需效能處理，先量測並保留數據與外形契約。

## 擴充與驗證

先確認用途、狀態與責任，再找既有主題、helper 及元件。差異只在內容與回呼時優先組合；有獨立狀態或可重用新責任才擴充或新增。引入套件需有具體問題、責任位置與維護收益，不為單一功能加入第二套翻譯、主題或狀態管理。

檢查桌面／手機、窄／寬／矮畫面、長名稱、空值、Loading、Disabled、Error、焦點、返回及主要操作可達性；共用元件變更要核對呼叫端。自動測試保護行為與契約，不為每個色碼或間距新增鏡像斷言；真實布局、觸控、WebGL 與原生 dialog 仍需實際瀏覽器檢查，見 [測試與驗證](測試與驗證.md)。
