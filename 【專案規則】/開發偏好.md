# 開發偏好

使用者固定的程式品質與產品偏好。只檢查本次任務適用的規則。

## 程式設計

- 類別、函式與元件保持責任集中,避免不必要的跨層耦合。
- 有獨立狀態或策略的邏輯,優先隔離成可獨立測試的單位;無狀態轉換優先使用純函式,不為拆分而建立多餘類別。
- 跨層依賴遵守專案既有的注入與介面方式,不依賴其他層的內部型別或可變狀態。
- 優先重用既有能力;只有能隔離責任、降低耦合或改善測試時才新增抽象。

## 常數與單一來源

- 設定、門檻、倍率、時間值、共用名稱與重複字串應有清楚的單一來源。
- 不在業務邏輯散落 Magic Number 或重複字串。
- 單純、語意明確且不會調整的區域值可以留在使用處,不為集中而集中。

## UI/UX

任務涉及使用者介面時:

- 優先沿用現有版面與互動模式,保持整體統一。元件依用途與責任共用;有獨立需求時可以組合、擴充或新增,不為外觀相似而強制共用。
- 介面保持簡潔、清楚且好操作,不加入不必要的元素、提示或冗長文字。
- 新功能不得讓主要操作流程不必要地變複雜。
- 考慮必要的 Loading、Disabled、Error、空狀態與返回行為,但不為每種狀態增加多餘介面。
- 顏色與共用樣式使用專案主題或具名的語意來源,避免各頁散落硬編碼;沿用目前的主題與語系；若任務另行擴充主題，再檢查各主題的可讀性。
- 遵守專案指定的設計系統、語系、無障礙與平台慣例。

## 使用者文字與語系

- 網頁使用者可見文字沿用 `src/i18n/zh-TW.ts`；本機啟動訊息使用 `scripts/messages.json`。不得在 UI 邏輯硬編碼文字或另建一套語系機制。
- 目前介面為繁體中文；新增或修改文字沿用既有 key 與格式，不因文件規範自行新增英文或深色模式。
- 修改既有文字 Key 前先搜尋所有使用位置。
- 技術 Log、內部識別字與協定內容不當作 UI 翻譯文字。

## 註解

- 註解只說明非直覺的原因、限制、相容性需求或設計取捨。
- 不逐行描述程式碼正在做什麼;能用清楚命名表達時不另外加註解。
- 不加入「新增」、「修正」、「修改」等變更標記。
- 不在 Code 中保存 Changelog;修改歷史交給版本控制。
- 修改實作後同步刪除失效註解。

## 本專案的修改邊界

- 幾何核心、重量公式、格式、保存與呈現各負其責；手機／電腦及報告沿用相同計算語意，不各寫一套公式，也不為介面統一強制共用所有狀態。
- 完整輪廓是幾何來源；供切線判斷的取樣與顯示用網格不得反過來取代它。格式化與顯示取位不回寫計算或保存數值。
- 規範是新修改的品質方向，不表示全部舊 Code 已符合；超出任務的程式落差記入 [待辦](docs/待辦與已知限制.md)，不藉整理文件自行重構或改功能。
