# 球棒體積

點兩下 `啟動.cmd`，會以預設瀏覽器開啟已建置的程式。這台電腦已有 Node.js，不需要先安裝開發套件。服務只監聽本機，重複啟動會使用同一個程式服務。

啟動檔可處理中文與含空格的專案路徑，直接尋找專案 runtime、PATH、使用者工具目錄及一般 Node.js 安裝位置。找不到執行環境時，Windows PowerShell 以 UTF-8 讀取集中管理的訊息，顯示中文錯誤並保留視窗；找到後直接執行 Node.js，背景服務啟動完成即可結束啟動流程。

選擇 `.anc`，自動得到切除後的估算體積、長度、最大直徑與最細握把直徑。新增檔案會加入目前結果，保留既有分析與要求重量。手機寬度只顯示單支資料卡；電腦的單檔與多檔統一顯示「計算結果」表格，點檔名才開啟資料與 3D 預覽。預覽能切換整枝及切除後的外型，左鍵旋轉、右鍵平移、滾輪縮放，保留兩條切線，並以截面圈與小標籤顯示最大直徑、最細握把直徑的位置。切線、尺寸與體積來自同一份分析結果，不需要確認或手動調整。

畫面體積以 cm³ 顯示並四捨五入到整數，長度與直徑以 mm 顯示並保留一位小數。格式集中在 `src/lib/format.ts`；分析、切線、3D 座標仍使用完整精度，顯示的小數位不代表實物精度。

電腦從同一個上傳入口選擇一個或多個 ANC，都使用同一個結果表格，一個檔案是一列、多個檔案是多列。預設依序顯示檔案、體積、木料重量、預計重量；長度及兩項直徑可從「顯示資訊」打開。可依檔名或數據切換升降排序、下載 Excel 或 PNG。排序使用完整數值，重量範圍先比較下限再比較上限，無法判斷的值放在最後；檔名採自然順序。點檔名才開啟單支資料與 3D。新增檔案加入目前清單，只分析新檔案，既有結果與要求重量保留。先按垃圾桶進入移除模式，表格旁才出現圓形 ×；按 × 立即移除該支及其要求重量，取消該支未完成的分析。按勾勾退出模式。移除工具屬於畫面操作，不納入 Excel 或 PNG 報告。

「木料設定」提供可調整的參考密度（g/cm³）、木料體積（cm³）、木料重量（g）與實測重量誤差（%），初次四項皆空白。空白誤差計算時當作 0%，儲存及重開仍顯示空白；沒有預設密度。體積與重量皆有效時採用重量／體積的實測密度，否則採用已填的參考密度；都沒有有效密度時不估算重量。按「套用」才更新整批並保存設定；取消不改變已套用資料。設定保存於目前瀏覽器及網址的 localStorage，重新開啟同一個網址會還原；不同瀏覽器或網址不共用，清除網站資料後會回到空白。保存失敗時仍可於本次使用。舊版已保存的密度、體積、重量與誤差保留，不把既有設定當作預設而抹除。

每列除檔名之外可點擊輸入要求重量，也可聚焦該列後按 Enter。輸入下限按 Enter 後接著輸入上限，再按 Enter 才提交。上下限需為正數、上限不得小於下限，相同數值代表固定重量；Escape 或點到其他地方會取消未完成輸入，編輯器的 × 可清除要求。已提交的要求會隨最新一批檔案保存；未提交草稿不保存。

「預計重量」未填要求時，使用切除後球棒體積 × 有效密度 ×（1 + 實測重量誤差／100），沒有有效密度顯示 —。例如實物比預計輕 3%，填 −3，自動估算乘以 0.97。填妥要求後，預計重量固定為要求上下限，不再套用乘法；所需木料重量為要求上下限 × 木料體積／切除後球棒體積，再除以（1 + 實測重量誤差／100），−3% 就除以 0.97。固定要求模式不需要密度；誤差在兩種模式各套用一次。誤差需大於 −100%，空白等同 0%。校正不改木料實測重量、體積、採用密度或球棒幾何結果。未填要求時，木料重量仍是原本的木料參考重量；已填木料體積及重量時為輸入重量，只有體積及密度時為體積 × 密度。缺少有效木料體積時顯示 —；球棒體積無法判斷時不產生所需木料重量，木料體積小於球棒體積時顯示「木料體積不足」。預計重量固定以 g 顯示並四捨五入到整數，計算及排序保留完整精度。

網站自動保存最新一批 ANC 的完整原始內容、檔名、各支已提交的要求重量，以及顯示欄位、排序依據與方向，使用 IndexedDB 存 Blob，不轉成大型同步 JSON，也不保存電腦檔案路徑。重開同一瀏覽器、同一網址時自動恢復，重新走同一條分析流程；不用重新選原檔案，原 ANC 移動位置也不影響。只保存目前清單，新增與移除後更新同一份暫存，不累積歷史批次。重量編輯與顯示／排序操作各自只更新小份設定，不重新儲存 ANC，也不重新分析。重新整理、重開、切換手機／電腦版、新增或移除部分檔案均保留這批顯示設定；移除所有或最後一支回到上傳主頁，才恢復預設顯示欄位（體積、木料重量、預計重量）與檔名升冪排序。舊暫存缺少顯示設定時採預設，設定損壞不影響原檔案還原。保存失敗會提示；清除網站資料、換瀏覽器或網址不會帶過去。

結果畫面右下方是白底圓形垃圾桶與深灰底「新增檔案」。按垃圾桶進入移除模式，圓形按鈕上移並變成勾勾，中間展開同尺寸的「移除所有」；按勾勾收合恢復布局。動態效果尊重系統減少動態設定。移除所有或移除最後一支後取消分析與報告、刪除檔案及要求重量，立即回到上傳頁，重開也維持上傳頁；木料密度、體積、重量、誤差與重量單位皆保留。上傳頁不顯示懸浮按鈕，仍用中央上傳入口。手機維持資料卡，新增後逐支顯示，移除模式在卡片旁提供 ×。

下載入口的「圖片 · PNG」產生 PNG 報告，包含整批資料、目前選擇的欄位與排序、無法判斷的原因及單位。圖片與 Excel 都直接從「檔案」與數值欄位標題開始，不放報告名稱、檔案數、排序說明或日期。檔名與原因完整換行，不截成螢幕可見的幾列，也不包含操作按鈕或 3D。過大的報告會先降低圖片倍率；若超過單張圖片限制，會提示分批下載，不會偷偷省略資料。手機維持單檔選取和資料卡，不顯示批次操作。

下載入口為「下載報告」，可選 Excel（A4 直式）或 PNG 圖片。Excel 保留目前顯示的欄位與排序，體積及尺寸以完整精度的數字儲存，再用數字格式呈現整數體積與一位小數的尺寸。預計重量的單一估算以完整精度的數字儲存，重量範圍以文字保留兩端，木料重量直接顯示數字或範圍，不顯示「參考／建議」標示，單一木料重量以完整精度的數字儲存；固定要求重量則為數字。未知值維持「—」，原因留在檔名下方。檔名換行、列高與欄寬會預先安排；列印範圍只包含報告，設定 A4 直式、寬度一頁、高度不限、自動向下換頁、每頁重複欄位標題與水平置中。實際頁數由 Excel 的列印引擎及印表機決定，可在列印預覽查看，不會强迫整批縮到單頁。

單支、表格與圖片均以「體積」為標題，仍計算切除後的範圍。表格與圖片不設狀態欄，無法判斷的原因放在完整檔名下方，未知數值維持「—」。電腦表格與下載報告以預計重量使用較大的數字與淡底色；數值靠右、檔名靠左。網頁、圖片及 Excel 的欄寬依整批資料中的最寬內容計算，包含欄位標題、單位、格式化數值、檔名及原因；依顯示格式衡量寬度，不改原始數值。檔名欄設最小與最大寬度，超長內容完整換行；數值欄保留字體所需空間與留白。整張表格收窄並置中，圖片左右留白一致。網頁寬度不足時先收窄檔名欄，數值不縮字，極端寬資料可水平捲動。Excel 先安排 A4 寬度內的檔名欄，再依既有設定列印。單支移除體積下方的估算說明，表格與圖片移除校準說明；計算精度、規則及單支切線詳情不受文字調整影響。

## 重量單位與介面

排序控制外觀相連，左側保留目前欄位名稱，名稱後方為升／降冪箭頭，點擊左側切換排序方向；右側較小的下拉箭頭選擇排序欄位。名稱與方向維持白底、原本灰色文字；新增檔案、移除所有、排序欄位選擇箭頭及下載報告使用深灰底、白色文字或圖示，其餘工具維持白底灰框。

桌面「顯示資訊」內的「木料重量單位」可切換 g、oz 或兩者，並另外記住瀏覽器的選擇，與木料設定一樣，清空檔案重新開始仍保留。選擇只影響木料重量欄位及相應報告；預計重量、要求重量輸入與木料設定的重量輸入皆維持 g。g 顯示整數，oz 顯示小數一位（1 oz = 28.349523125 g）；兩者同格分兩行，以 g 為主要數字、oz 為次要數字。內部木料設定、要求重量、計算及排序始終使用未經顯示四捨五入的 g，切換不會重寫重量；參考密度仍為 g/cm³。

PNG 與 Excel 使用同一組單位及顯示資料。單一單位 Excel 重量保留完整精度數字與相應格式，雙單位用同格兩行文字保留各端值；A4 直式、重複表頭與自動分頁保持原設定。畫面與報告共用灰階色盤，預計重量仍以大字及淡灰底呈現。工具列的顯示資訊、排序及下載報告使用一致選單外觀，點外面、按 Esc、切到另一選單或選定排序欄位會收合。

## 計算的適用範圍

目前解析毫米、絕對座標、G0/G1 的 Y/Z 球棒輪廓，選取最後一趟涵蓋完整長度的進給路徑。排除快移、機械座標回原點及末端退刀。暫時將 Z 視為半徑；從兩端定半徑的預留段與棒身交界推定切線。

這是程式輪廓估算，尚未用實物驗證刀具偏移、打磨量及實際鋸切位置。檔名中的刀片寬度不會直接當作半徑修正或切除量。請先用已知尺寸與實際切線的樣本校準 `src/config/analysis.ts`，才適合把結果視為實物尺寸。沒有足夠依據的檔案會顯示無法判斷，不產生猜測體積。

裁切時以線性半徑內插；每段使用圓台公式 `π × L × (r₁² + r₁r₂ + r₂²) / 3` 積分。內部單位 mm³，畫面換成 cm³。3D 的裁切模型使用計算時的同一組裁切輪廓。

長度是裁切輪廓的兩端座標差，最大直徑是其中最大的半徑乘以二。它們與體積使用同一份裁切輪廓；切除範圍改變時，尺寸隨之重新計算。

最細握把直徑另外辨識輪廓語意。現有規則比較兩端內側區域的平均半徑，辨識較細的一端，再檢查棒尾凸起、凸起後的內部低谷，以及朝棒身方向重新變粗的特徵。平均半徑按軸向長度加權，不受密集或稀疏點位比例影響；握把區域的邊界以半徑等值交點內插。此區域只用於找握把最細處，不會改變球棒切線或體積，不會從體積中扣掉棒尾凸起。

無法辨識握把、最細處落在搜尋邊界、出現多個明顯低谷或規則互相矛盾時，握把直徑顯示「無法判斷」，其他已成功計算的尺寸與體積保留。規則目前針對現有棒形，仍需實物驗證；它不是所有球棒通用的握把區域定義。

## 開發

使用 Node.js 22.12 以上或 24 LTS。依賴版本已固定。

```sh
npm ci
npm run dev
npm test
npm run build
```

## 架構

| 位置 | 用途 |
| --- | --- |
| `src/domain/anc` | 解析 ANC、取得最終輪廓 |
| `src/domain/cuts` | 可替換且有版本的切線策略與登錄 |
| `src/domain/grip` | 可替換且有版本的握把區域策略與登錄 |
| `src/domain/geometry` | 輪廓裁切、體積積分、裁切後尺寸 |
| `src/domain/analyze.ts` | 統一分析結果，讓顯示與計算共用資料 |
| `src/domain/weight.ts` | 獨立的木料密度、參考重量與建議重量公式 |
| `src/services/material-storage.ts` | 有版本與驗證的木料設定保存 |
| `src/services/latest-session-storage.ts` | 最新一批 ANC 與要求重量的非同步保存、原子替換與清除 |
| `src/services/batch-session.ts` | 最新一批資料格式、驗證與原始 File 還原 |
| `src/domain/batch-display.ts` | 顯示與排序的共用型別、預設、舊資料驗證與還原 |
| `src/config` | 校準值、規則參數、介面斷點 |
| `src/workers` | 在背景執行分析 |
| `src/services` | 共用單檔分析、限制同時工作數的批次佇列與取消處理 |
| `src/services/analysis-worker-pool.ts` | 預載及重複使用背景分析程式，管理取消、故障與釋放 |
| `src/features/batch` | 批次表格、欄位定義、排序與共用報告資料模型 |
| `src/reports` | PNG 與 Excel 報告，不依賴表格 DOM 或 3D |
| `src/components` | 結果卡、電腦 3D、基本元件 |
| `src/i18n` | 集中管理介面文字與錯誤訊息 |
| `scripts` | 本機服務、啟動程式與啟動訊息 |
| `tests/fixtures` | 目前 43 個 ANC 的程式交界回歸樣本 |

新增棒形規則時實作 `CutStrategy` 並登錄到 `src/domain/cuts/registry.ts`；不需改動體積公式或畫面。多個規則產生互相矛盾的切線時停止計算。幾何校準與切線規則分開，避免刀具修正混入 UI。

批次與單支呼叫同一份分析核心。批次表格與報告共用 `buildBatchView`，欄位的取值、單位及格式集中在 `src/features/batch/columns.ts`，內容欄寬規則位於同資料夾的 `column-layout.ts`。各 renderer 提供自己的字體、留白、寬度限制與文字量測方式；瀏覽器使用 Canvas 依實際字體量測，Excel 的伺服器測試使用字元寬度估算。日後新增報告格式可使用同一資料模型與欄寬規則另外實作 renderer，不需改切線策略；批次工作數與圖片限制分別集中在 `src/config/batch.ts` 和 `src/config/report.ts`。

Excel renderer 位於 `src/reports/excel-report.ts`，列印及字體設定在 `src/config/excel.ts`，共用下載處理位於 `src/reports/download.ts`。ExcelJS 只在選擇 Excel 下載時載入，手機畫面與尚未選擇 Excel 下載時不會載入這個套件。

重量核心不依賴 React、切線規則或瀏覽器保存。`weight-input.ts` 驗證輸入草稿，`weight-editor.tsx` 管理 Enter／取消的編輯流程，`material-dialog.tsx` 管理木料設定草稿，`use-material-settings.ts` 將保存服務接到 UI。表格、排序與兩種報告均使用 `buildBatchView` 的相同重量結果。日後改重量公式只需修改重量核心；新增切線算法仍由既有切線策略擴充。

`batch-toolbar.tsx` 管理顯示資訊、排序、下載選單及選單收合；結果頁管理重量編輯與報告生成。工具列不執行分析或重量公式。重量單位格式集中在 `weight-display.ts`，由欄位資料決定換算範圍，報告不另算一份重量。

`use-batch-session.ts` 協調最新一批、要求重量與顯示設定，連接分析 hook 和獨立保存服務；結果表格接收相同的要求資料，不自行管理另一份要求或瀏覽器儲存。保存服務的寫入序列避免舊批次較慢的儲存覆蓋新批次或清除操作。檔案、要求與顯示設定以同一個 IndexedDB 交易替換；要求和顯示設定各自附上批次識別碼，避免套用到另一批。表格的欄位與排序改由 session hook 提供單一來源，只回報使用者操作；預設及驗證集中在 `batch-display.ts`，不依賴 React 或瀏覽器。還原過程若已新增、移除或清除，忽略過期還原結果。木料設定不屬於這個資料庫，清除批次不會重置設定；保存格式與資料庫設定集中在 `src/config/session.ts`，日後擴充欄位或換保存方式不需改切線和重量公式。

`useAnalysis` 為本次頁面建立背景分析服務，頁面載入後預先載入最多兩個 Worker，分析完成後保留給下一個檔案或批次。檔案讀取、UTF-8／Big5 解碼與格式限制仍在 `analyze-file.ts`，幾何分析仍在領域核心。各工作使用獨立識別碼；`incremental-analysis.ts` 管理跨次新增共用的有界佇列，新增不重新分析既有檔案。移除單支取消該支，清除取消全部，晚到結果不會重新插入已移除檔案。取消或故障的 Worker 會終止並在下一次工作時重建，頁面卸載釋放所有 Worker。首次網路載入仍需要時間，預載將這段移到選檔前，重複使用減少逐檔啟動成本；不保證不同網路或電腦的時間完全相同。

握把規則實作 `GripStrategy` 並登錄到 `src/domain/grip/registry.ts`，參數集中在 `src/config/analysis.ts` 的 `gripParameters`。切線策略與握把策略獨立；前者決定保留哪一段木材，後者判斷保留段中的握把區域。新增尺寸時從 `BatDimensions` 與尺寸模組擴充，顯示標籤集中在 `src/i18n/zh-TW.ts`。

樣本測試驗證的是程式解析與交界，並非實物鋸切位置。42 個樣本可辨識兩端交界與握把最細處，1 個沒有完整尾端預留段，會顯示無法判斷。尺寸樣本期望值位於 `tests/fixtures/dimensions.json`。另外測試切除最大直徑的位置、反向棒形、點位密度、端部尖點、非典型多低谷，以及未來規則的矛盾情況。
